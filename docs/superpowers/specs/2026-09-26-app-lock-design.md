# Блокировка приложения (PIN + Touch ID) — дизайн

Релиз: 0.1.4. Статус: согласовано в брейншторме 26.09.2026, ждёт ревью спеки.

## Цель и границы

Защитить данные от человека за незаблокированным компьютером (член семьи, коллега). Это замок на двери приложения,
а не шифрование: база в `userData` остаётся обычным файлом SQLite, токены — как сейчас (safeStorage). Кто имеет доступ к
файлам учётной записи, прочитает их и без приложения. Эта граница пишется одной строкой в тексте раздела настроек.

Не входит в 0.1.4: Windows Hello (нужен нативный модуль; можно добавить позже тем же интерфейсом «способ разблокировки»),
шифрование базы, блокировка будущего MCP-режима (записать в бэклог: когда приложение станет MCP-сервером, замок должен
распространяться и на него).

## Способы разблокировки

- **PIN** — на всех ОС, обязателен при включении блокировки. Только цифры, 4–8 знаков. Запрещены все одинаковые
  (`0000`, `111111`) и сплошные возрастающие/убывающие последовательности (`1234`, `98765`).
  Ввод — поле + кнопка «Войти» (Enter).
- **Touch ID** — только macOS и только если `systemPreferences.canPromptTouchID()`; включается отдельным переключателем
  (по умолчанию вкл., если доступен). `promptTouchID` в Electron использует `kSecAccessControlUserPresence`, поэтому
  системный диалог сам предлагает пароль Mac, если отпечаток не прошёл. PIN всегда остаётся запасным способом.

## Когда блокируется

Каждый триггер — отдельный переключатель в «Блокировке», **по умолчанию все включены**:

| Триггер | Источник |
|---|---|
| При запуске приложения | старт main |
| После 60 минут без активности | `powerMonitor.getSystemIdleTime() >= 3600`, проверка раз в минуту (простой системы, не только окна) |
| При блокировке экрана | `powerMonitor` `lock-screen` |
| При уходе в сон | `powerMonitor` `suspend` |

Всегда доступно (не триггер, а действие): «Заблокировать сейчас» — кнопка в настройках и пункт меню `CmdOrCtrl+L`.
Если все триггеры выключены, блокировка срабатывает только вручную.

## Поведение

- Существующие и новые пользователи узнают о функции из разовой плашки на главном: «Новое: блокировка по PIN или
  Touch ID» + «Включить» (→ настройки) / «Не сейчас». Видна, пока блокировка выключена и «Не сейчас» не нажато;
  «Не сейчас» — в `localStorage` (удобство, не данные). Само обновление до 0.1.4 ничего не блокирует.
- Блокировка выключена по умолчанию. Включение: PIN дважды → «Готово». Смена PIN — после ввода текущего PIN;
  выключение — после текущего PIN или Touch ID.
- Экран блокировки: название приложения, поле PIN, кнопка «Touch ID» (если включён), строка «Идёт импорт» без цифр,
  если импорт работает.
- Неверный PIN: первые 5 попыток без паузы, дальше пауза перед следующей попыткой 30 с → 1 мин → 5 мин → 15 мин
  (потолок, дальше каждая ошибка — 15 мин). Экран показывает, через сколько можно попробовать. Счётчик и время хранятся
  на диске: перезапуск их не сбрасывает. Верный PIN или Touch ID обнуляет счётчик.
- «Забыли PIN?» (видно всегда после 5-й ошибки) → «Удалить все данные» через тот же системный диалог. Другого сброса нет.
- Импорт, синхронизация и проверка/скачивание обновлений работают под замком (они живут в main и worker). Установка
  обновления («Перезапустить и обновить») — только после разблокировки. Уже скачанное и проверенное обновление всё же
  ставится при выходе из приложения (Windows, Linux AppImage), даже под замком: это не действие пользователя под
  замком и данных не показывает.

## Защита в main

- **IPC-шлюз.** `registerIpc` (`apps/desktop/src/main/ipc.ts`) получает `isLocked()`; порядок проверок:
  отправитель → **замок** → аргументы → обработчик. Под замком проходят только методы `ALLOWED_WHEN_LOCKED`:
  `getLockState`, `unlockWithPin`, `unlockWithTouchId`, `deleteAllData`. Остальные — фиксированная ошибка
  `LOCKED = 'Приложение заблокировано'`.
- **Push-события** под замком: уходит только `balance:lock` и флаг «импорт идёт» (boolean). Прогресс импорта,
  статус обновлений и прочее не отправляются; после разблокировки renderer перечитывает всё сам.
- **Очистка renderer.** При блокировке main делает `webContents.reload()`: всё, что окно уже показало, пропадает из
  памяти. После перезагрузки guard видит `locked` и открывает экран блокировки.
- **Меню.** Под замком «Настройки…» (`CmdOrCtrl+,`) ничего не делает; «О программе» работает (данных нет).
- Новые методы IPC (все с zod-схемой): `getLockState`, `unlockWithPin(pin)`, `unlockWithTouchId()`, `lockNow()`,
  `enableLock(pin)`, `changePin(current, next)`, `disableLock({ pin } | { touchId: true })`,
  `setLockTriggers({ startup, idle, screenLock, sleep })`, `setTouchId(enabled)`. PIN в схеме — `^\d{4,8}$`.
  Методы настройки (кроме `getLockState`/`unlock*`) под замком запрещены шлюзом.

## Хранение

`userData/lock.json`, права 0600, запись атомарно (tmp + rename):

```json
{
  "version": 1,
  "kdf": { "name": "scrypt", "N": 32768, "r": 8, "p": 1, "salt": "<base64 16 байт>" },
  "hash": "<base64 32 байта>",
  "touchId": true,
  "triggers": { "startup": true, "idle": true, "screenLock": true, "sleep": true },
  "failedAttempts": 0,
  "nextAttemptAt": null
}
```

- Файла нет → блокировка выключена. PIN нигде не хранится, сравнение — `crypto.timingSafeEqual`.
- Файл не читается или не проходит схему → приложение **остаётся заблокированным**, доступна только «Забыли PIN?» →
  «Удалить все данные». В лог — только факт, без содержимого.
- `lock.json` и `lock.json.tmp` добавляются в `APP_FILES` (`apps/desktop/src/main/wipe.ts`): удаление данных снимает и
  блокировку.

## Модули

Main (`apps/desktop/src/main/lock/`):

- `pin.ts` — правила PIN, хеш и проверка (scrypt из `node:crypto`). Чистые функции.
- `state.ts` — машина состояний: `locked | unlocked`, ошибки, пауза. Часы передаются снаружи. Без Electron.
- `store.ts` — чтение/запись `lock.json` (zod-схема), атомарная запись.
- `service.ts` — `LockService`: собирает всё вместе, даёт обработчики IPC и `isLocked()` для шлюза, реагирует на триггеры.
- `electron.ts` — единственное место с `powerMonitor` и `systemPreferences` (как `update/electron.ts`).

Renderer (FSD):

- `entities/app-lock` — Pinia-store состояния (`locked`, `enabled`, `touchIdAvailable`, пауза), `api/useAppLockRequest.ts`.
- `features/app-lock` — `AppLockFeature.vue` (экран разблокировки) и `AppLockSettingsFeature.vue` (включить / сменить PIN /
  выключить, переключатели триггеров и Touch ID, «Заблокировать сейчас»). Логика включения и выключения — внутри фичи.
- `pages/lock` — тонкая оболочка над `AppLockFeature`; маршрут `ROUTE.lock`.
- `widgets/settings` — нынешняя композиция `pages/settings/SettingsPage.vue` переезжает сюда как есть (карточки
  подряд) плюс карточка `AppLockSettingsFeature`. `SettingsPage` становится тонкой оболочкой над виджетом.
  Раскладка с меню по макету `.superpowers/brainstorm/settings-page.html` — отдельный будущий рефактор, не в 0.1.4.
- `app/router/guards.ts` — если `locked`, любой маршрут → `ROUTE.lock`; с `ROUTE.lock` без замка → главный.
- `app/listeners.ts` — подписка на `lock`.

Якоря доверия не затрагиваются: `release.yml`, `.claude/settings.json`, safety-тесты, нативных модулей нет.

## Тесты

- `pin`: хеш/проверка, неверный PIN, правила (длина, только цифры, одинаковые, последовательности).
- `state`: 5 попыток без паузы, лестница пауз и потолок, попытка во время паузы отклоняется без проверки PIN,
  сброс после успеха, восстановление счётчика из файла после «перезапуска».
- `store`: круговая запись/чтение, права 0600, повреждённый файл → `locked`, без файла → выключено.
- IPC-шлюз: для каждого метода из `METHODS` под замком — отказ `LOCKED`, кроме `ALLOWED_WHEN_LOCKED`
  (новый метод автоматически попадает в проверку); порядок «отправитель → замок → аргументы».
- Триггеры: каждый включённый переключатель блокирует, выключенный — нет (powerMonitor и часы — моки).
- `wipe`: `lock.json` в `APP_FILES` и удаляется.
- Меню: пункт `CmdOrCtrl+L`; «Настройки…» под замком не отправляет `open-settings`.
- Renderer: guard уводит на `lock`; архитектурный тест проходит с новыми слайсами.
- Touch ID и реальный `powerMonitor` — ручной смоук пользователя (чек-лист в отчёте).
